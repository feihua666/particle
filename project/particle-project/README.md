# particle-project 项目集成方案

## 项目概述

particle-project 是一个项目集成方案，将多个业务组件进行统一集成，形成一个单体应用的启动器。

## 核心功能

- **组件集成**: 整合所有业务组件（area、cms、crm、user、dept、role 等）
- **单体启动**: 提供统一的启动入口，一键启动所有集成的组件功能
- **统一配置**: 集中管理各组件的配置信息
- **依赖协调**: 处理组件间的依赖关系和版本兼容性

## 架构说明

该方案采用模块化设计，通过 Spring Boot 的自动装配机制，将各个独立的业务组件无缝集成到一个应用中，实现：

- 统一的身份认证与授权
- 共享的数据源和缓存配置
- 一致的服务治理策略
- 集中的日志和监控管理

## DDD 架构支持

particle-project 保留了完整的 DDD（领域驱动设计）四层架构模块：

- **adapter**: 适配层，处理外部接口和协议转换
- **app**: 应用层，编排业务流程和用例
- **domain**: 领域层，核心业务逻辑和领域模型
- **infrastructure**: 基础设施层，技术实现和数据持久化

### 开发模式选择

根据业务特点，提供两种开发方式：

**1. 垂直业务组件模式**
- 适用场景：业务相对独立、边界清晰、可复用性强
- 开发方式：在 `component` 目录下新建独立模块
- 集成方式：在 particle-project 中引入依赖即可
- 优势：高内聚低耦合、便于独立维护和复用

**2. 综合业务开发模式**
- 适用场景：业务关联紧密、跨领域协作频繁、无需独立部署
- 开发方式：直接在 particle-project 的四层模块中开发
- 集成方式：天然集成，无需额外配置
- 优势：开发效率高、减少模块间通信开销

## 使用方式

项目提供多种启动器，满足不同场景需求：

### particle-project-start
- **定位**: 全功能完整启动器
- **功能**: 集成所有业务组件的完整应用系统
- **默认端口**: 8008
- **适用场景**: 完整功能演示、全量测试、生产环境

### particle-project-lite-start
- **定位**: 基础轻量级启动器
- **功能**: 运行核心业务功能
- **默认端口**: 8009
- **适用场景**: 生产环境、快速部署、资源受限环境

### particle-project-dev-start
- **定位**: 开发专用启动器
- **功能**: 核心业务功能 + 定向开发模块
- **默认端口**: 8007
- **适用场景**: 日常开发、快速验证、功能测试
- **优势**: 聚焦当前开发模块，减少无关组件干扰，提升开发效率
