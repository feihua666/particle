# Particle 是什么？

[Particle](https://github.com/feihua666/particle) 是一个基于 SpringBoot、Vue 前后端分离的快速开发脚手架。后端以 Springboot 驱动，基于DDD领域设计理念，面向业务垂直拆分模块；前端以 Vue 驱动，结合 Element Plus UI 封装常用组件并完成对接后端业务功能。旨在快速开发 或 以此为基础组织新模块/项目。

## 使用场景

- **直接使用**

  Particle 是一个基于 SpringBoot、Vue 前后端分离的快速开发脚手架。同时已经内置了很多功能如：用户管理、角色管理、权限管理、字典管理、区域管理等满足大部分开发需求。内置的功能会越来越多，如果内置的功能已经满足你的需求，那么可以直接使用。目前已经内置的 数据查询功能 可以实现动态数据查询，动态编写SQL 查询或脚本，而无需重新打包和发布系统，还可以结合 开放平台 功能快速实现开放平台，对外提供 API 接口服务。

- **二次开发**

  如果需求比较复杂或内置的功能不能满足需求，完全可以基于此快速开发，内置的 低代码功能 可以方便的生成统一并满足开发规范的模块和常用的CRUD代码，包括对应的前端页面代码，方便快速开发。

## 软件架构

  Particle 面向通用业务开发，将常用业务功能抽象或提取通用性并落地形成通用业务模块。通用业务模块可以被其他模块或项目依赖使用，以实现快速组装可用的新模块或项目。Particle 模块化开发，基于DDD领域驱动设计，将业务模块进行垂直拆分，每个模块只负责一个业务功能，每个模块之间通过接口进行通信，模块之间可以进行组合，实现业务功能。

- **后端**

  1.  全局组件  
      全局组件通常定义为与业务无关，主要关注面向技术的封装，这些组件通常为 global 的子模块如：global-dto、global-exception
  2.  业务模块  
      业务模块通常是垂直拆分后的一个独立的业务功能，定位是服务运行的最小单位，可以单独发布或多个业务模块组合成更大的模块发布为一个项目，这些组件通常为 component 的子模块如：user、dict、func、area
  3.  项目启动器  
      要运行一个项目需要一个启动器，启动器通常定义为项目启动的入口，将业务模块进行集成，并完成对应的配置，用来部署和发布，这些通常为 project 的子模块如：particle-project
  4.  DDD 领域设计四层架构规范  
      DDD 领域设计四层架构规范是为业务模块而生，提供了框架规范，这些规范为 common 的子模块如：common-adapter、common-app、common-client、common-constant、common-domain、common-infrastructure

- **前端**

  1.  全局组件或工具  
      全局组件通常定义为与业务无关，主要关注面向技术的封装，这些组件通常为 web/global 目录下的如：全局相关 common 目录、pc或平板端大屏使用的 pc 目录、移动端使用的 mobile 目录
  2.  业务模块  
      业务模块通常是垂直拆分后的一个独立的业务功能，定位是服务运行的最小单位，可以单独发布或多个业务模块组合成更大的模块发布为一个项目，这些组件通常为 web/componnent 目录下的如：pc或平板端大屏使用的 pc 目录、移动端使用的 mobile 目录
  3.  项目启动器  
      要运行一个项目需要一个启动器，启动器通常定义为项目启动的入口，将业务模块进行集成，并完成对应的配置，用来部署和发布，这些通常为 web/project 目录下的如：particle-project 目录
  4.  架构规范  
      定义一些规范如：接口定义、数据结构定义。这些架构规范主要为业务相关规范定义，架构规范为 web/common 目录下的相关定义，这些定义通用定义通用的对应后端数据对接的一些常用的数据结构定义
